Data Pipeline Check #1 (Nursery Scenario)
File 1: batch101.csv
1. What information does this file record? This file records information about different people being detected in certain rooms at specific times and dates. Each record shows the person's ID, the type of person (parent, nurse, doctor, or patient), the room they were in, and when they were detected.
2. What kind of device do you think produced this file, and what in the data makes you think so? I think this file came from an ID scanner or badge reader, possibly in a hospital system that keeps track of patients, nurses, doctors, and visitors. Each person has their own ID number, and the file records the room where that ID was detected. It contains only people and rooms, with no measurements such as temperature, and a row is written only when someone is detected. These clues point to a device that reads a badge or wristband.
3. What identifies one record? No single column is unique on its own. The same person appears more than once (for example, N2001), and different people can be in the same room. A record can be identified by combining the PersonID, the date, and the time.
4. How are the fields represented? The fields are represented in different ways. The time is text written with AM and PM (for example, 5:12 PM), and the date is written in month/day/year format. Time and date are stored in two separate columns. The room is a number, and the PersonID is a letter followed by numbers. The first letter of the PersonID matches the person type: G = parent, N = nurse, P = patient, and D = doctor.
5. How many records are there? There are 40 records in the file (41 lines including the header row).
6. What do you notice about how the device actually collects and stores data? The device records information whenever someone is detected in a room, not at regular time intervals. Each row keeps the time, date, room number, and person's ID, and the rows are in time order. The same person can appear in different rooms at different times, so you can follow their path through the building. The file does not say whether a person is entering or leaving a room.
7. What are the advantages and disadvantages of this data format (CSV)? CSV files are simple, small, and easy to open in programs like Excel. They organize information into rows and columns, which makes the data easy to read. A disadvantage is that they do not explain what the information means, and they do not store data types (everything is just text). They are also not the best option for storing more complicated data.

File 2: stream101.json
1. What information does this file record? This file records the date and time, the room number, the room temperature in Fahrenheit, and whether the door is open or closed.
2. What kind of device do you think produced this file, and what in the data makes you think so? I think this file was produced by a smart thermostat or room monitor with built-in sensors. The file records the room temperature at regular 30-minute intervals, which suggests a temperature sensor on a schedule. It also records whether the door is open or closed, which suggests a door sensor. The timestamps show that every room is checked at the same set times.
3. What identifies one record? No single field identifies a record on its own. All four rooms are checked at the same time, so the dateTime repeats, and each room appears at every time, so the roomNumber repeats too. A record is identified by combining the roomNumber and the dateTime. For example, room 305 at 5:00 PM only appears once.
4. How are the fields represented? Each value in a record has a label in front of it, such as "roomNumber": 305. The dateTime is stored as one text field that holds both the date and the time (for example, "03/11/2026 05:00 PM"). The roomNumber is a whole number that identifies the room. The roomTempF is a number with a decimal (for example, 71.3) that gives the room temperature in Fahrenheit. The doorStatus is a text value, either "open" or "closed," that shows the state of the door at the time of the reading.
5. How many records are there? There are 36 records in the file. I counted them by using Ctrl+F in VS Code to search for each field name (dateTime, roomNumber, roomTempF, and doorStatus), and every search returned 36 matches. This matches the pattern in the data: the device records every 30 minutes from 5:00 PM to 9:00 PM, which is 9 time slots, and with 4 rooms that gives 9 x 4 = 36 records.
6. What do you notice about how the device actually collects and stores data? The device records on a schedule, not only when something happens. It takes a reading every 30 minutes, starting at 5:00 PM and ending at 9:00 PM, and every room gets a reading at every time slot. Each reading shows whether the door was open or closed at that moment. Because the status is only recorded every 30 minutes, we don't know what happened in between. For example, a door could open and close between two readings and the file would never show it. This is different from the CSV, which only writes a row when someone is detected, while this file writes a row on a schedule whether or not anything is happening.
7. What are the advantages and disadvantages of this data format (JSON)? An advantage of JSON is that every value has a label in front of it, such as "roomNumber": 305 or "doorStatus": "closed". This makes it easy to tell exactly what each value means without looking anything up. A disadvantage is that those labels repeat in every record, so the file is much longer than the CSV and looks like it holds more data than it really does. This also makes it harder to read at a glance. The CSV was easier to scan because it had less text on each line.

File 3: feed101 (1).xml
1. What information does this file record? This file records vital signs for patients at specific times. Each reading includes the date, the time, the patient ID, the heart rate in beats per minute, the breathing rate in breaths per minute, and the temperature in degrees Fahrenheit.
2. What kind of device do you think produced this file, and what in the data makes you think so? I think this file was produced by a patient monitor, such as a vital-signs monitor attached to each patient. It tracks heart rate, breathing rate, and temperature, which are all measurements taken from a person's body. Each reading is tied to a patient ID instead of a room, which shows the device is watching individual patients. The units in the file (bpm, breaths/min, and F) also show these are sensor measurements.
3. What identifies one record? No single field identifies a record on its own. Several patients are recorded at the same date and time, so the date and time repeat, and each patient appears at many different times, so the patientId repeats too. A record is identified by combining the patientId with the date and time. For example, patient P1001 at 17:00 on 2026-03-11 only appears once. The heart rate, breathing rate, and temperature are measurements, so they can repeat and can't be used to identify a record.
4. How are the fields represented? Each value in a record is wrapped in an opening and a closing tag, such as <heartRate>132</heartRate>, and each reading is wrapped in a <reading> tag. The date and time are stored as two separate fields, similar to the CSV. The date is written year-month-day with dashes (2026-03-11), while the CSV uses month/day/year with slashes. The time is written in 24-hour format (17:00) with no AM or PM, unlike the CSV and JSON. The patientId is the letter P followed by four numbers (for example, P1001). The heart rate, breathing rate, and temperature are numbers, and each one has a unit attribute (bpm, breaths/min, and F) that tells you what the number is measured in. This makes the XML more descriptive than the CSV, which has no units.
5. How many records are there? There are 196 records in the file. I counted them by using Ctrl+F in VS Code to search for the closing tag </reading>. Each record ends with exactly one of these tags, and the search found 196 matches. This matches the schedule in the data: readings every 5 minutes from 17:00 to 21:00 give 49 time slots, and with 4 patients at each time that gives 49 x 4 = 196 records.
6. What do you notice about how the device actually collects and stores data? The device records on a regular schedule, not only when something happens. It takes a reading every 5 minutes, starting at 17:00 and ending at 21:00. At each time, all four patients get a reading, so four records in a row share the same time, and then the time moves forward by 5 minutes. This gives 49 time slots with 4 patients each, which matches the 196 records I counted. Because it measures vital signs on a constant schedule, it collects much more data than the other devices. The CSV only writes a row when someone is detected, and the JSON records every 30 minutes.
7. What are the advantages and disadvantages of this data format (XML)? An advantage of XML is that it is very descriptive. Every value sits inside its own tag, and attributes such as unit="bpm" tell you exactly what each number means, which the CSV does not do. A disadvantage is that every value needs an opening and a closing tag, so the file is long and wordy and can be harder to read at a glance than the CSV. The time is also written in 24-hour format (17:00) with no AM or PM, which may be less familiar than the AM/PM style in the other files.
